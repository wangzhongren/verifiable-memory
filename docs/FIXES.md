# 公开版本修复：检查点与完整事件链

基线：`ab784856e259cd66dd65323883551f3332a58ee6`。

## 修复内容

- 修正 `store.py` 和自检中的包内导入，干净 checkout 可执行规则与完整测试。
- 操作编号以全局 `n_ops` 为准，每次成功提交递增；检查点重载不会复用旧编号。
- `checkpoint_state` 保存固定快照，`state` 保存最新缓存。每 512 条操作在同一写事务内复制快照并记录序号、状态哈希和事件哈希。重载从快照重放尾部，最后核对当前缓存。复制成本 O(N)，并非 O(1)。
- v2 每条完整事件携带前驱哈希和自身哈希。查询与错误即使不改变状态，也推进事件链。SQLite 提交同时核对事件链头、状态哈希与全局序号，避免读操作造成的并发盲区。
- 持久化失败回滚内存中的临时写入，不让后续操作沿用未提交的状态。
- `replay.py` 校验事件链及命令类别；`verify.py` 用独立实现校验事件链，并把重放报告绑定到证据文件 SHA-256。
- 错误消息中的已知名称按固定顺序输出，避免 SQLite 更正记录后的行顺序改变导致跨检查点重放失败。

## 兼容性与证明边界

新数据库格式为 `sqlite@v2`，新证据格式为 `session@v2`，状态和写证书的格式不变。两种存储后端的 v2 导出仍逐字节一致。

旧 v1 文件缺少完整事件链，不会被静默升级；本版本明确拒绝读取旧格式。保留旧库和原证据，使用对应旧版本读取；需要延续知识内容时，用知识 JSONL 导入另一个新库。新导入不是旧历史的可信迁移。未来若增加迁移命令，也必须明确记录迁移边界，不能声称补算哈希能够恢复历史来源的真实性。

工作路径只读取检查点之后的事件；历史段完整性由离线导出、重放、独立核验负责。事件哈希能检测未同步重算链的篡改，不能阻止控制整个文件的攻击者重写事件链和元数据，也无法在没有外部可信锚时识别完整旧版本回滚。查询内容的事实真实性、LLM 解析是否符合意图仍在该证明范围之外。
