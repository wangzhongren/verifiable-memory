# 可训练的分叉控制器（第一版）

有向图和向量增量仍由 [VECTOR_PROTOCOL.md](VECTOR_PROTOCOL.md) 定义。新增的控制器根据查询文本与当前实体，从**现有有效出边**中自主选择下一步；沿路径逐节点重复，直到到达叶节点、超过步数限制或弃权。控制器只选择，不改写实体、动作或边。

## 训练数据与接口

训练输入是 JSONL，每行一个分叉决定：

```json
{"source":"A","query":"向右然后向上","edge":"AB"}
{"source":"A","query":"向上","edge":"AD"}
{"source":"A","query":"无关请求","edge":null}
```

`edge` 必须是该源实体当前有效的有向出边；`null` 是明确的弃权标注。输入中的标注是否符合人类意图取决于训练数据质量，日志证明不了这一点。仓库的 [样例训练集](../examples/branch_policy_training.jsonl) 使用 `A→B`、`A→D`、`B→C` 的小图，供复现流程，不代表真实场景准确率。

训练集必须覆盖每条有效边的至少一个正例，以及每个有出边的源实体的至少一个弃权样本。缺少这些标注时拒绝训练，不把完全未学过的边或没有负例的分叉直接交给控制器。

先用 [向量协议](VECTOR_PROTOCOL.md) 建 A、B、C 和 `BC` 边，再额外建立 D=`[0,2]` 与 `AD` 边（复用上移动作 `[0,2]`），然后运行：

```bash
python3 cli.py --session graph.db policy-train \
  --data examples/branch_policy_training.jsonl --out branch.policy.json
python3 cli.py --session graph.db --json policy-route \
  --model branch.policy.json --source A --query "向右然后向上"
python3 cli.py --session graph.db policy-eval \
  --model branch.policy.json --data heldout.jsonl
```

模型文件独立于记忆库，用仅本人可读写的权限创建，拒绝覆盖。它包含从标注查询学出的字、相邻字组、当前实体名称及向量前 16 维正负号的权重。采用纯标准库多类 softmax 训练，不调用远端 LLM。模型固定随机种子和轮数，输入与图相同可重现训练结果；这仍只是有限动作集合中的小型策略分类器。

`heldout.jsonl` 应由用户用不同于训练集的真实标注样本准备。`policy-eval` 报告首步选边的正确数和弃权数，不改动数据库。仓库有一个未训练的改写“请先右移再上移”，样例模型会弃权；不要把训练集的 13/13 当作新问法的成绩。

路由时只考虑当前有效的出边，包含一个可学习的“弃权”选项。最高分的边未达到最小概率或与第二名差距不足时返回弃权，CLI 退出码为 **2**；路径成立且到达叶节点时为 **0**；配置或执行错误为 **1**。这里的 softmax 数值用于选择和诊断，未经真实数据校准，不应解释为事实正确的概率。未见过的问法可能被拒绝，也可能选错分支，需要独立评测。

控制器每次输出所选边、候选分数和模型文件 SHA-256。`route_entities` 再把这条路径送入既有确定性内核：它逐边检查方向、引用修订及 `v(B)=v(A)+Δ(a)`，记录每步槽哈希，允许完整重放和第二套实现核验。**核验器证明给定路径的运算成立；它不证明模型选择这条路径符合问题含义。** 没有附带模型文件时，导出的会话只保留其 SHA-256，不能独立重算模型的全部打分；模型文件与原训练数据应和证据一同保留。

模型训练时绑定当前有效图的指纹（边及其源实体、动作、目标实体的哈希）。新增边或更正关联实体/动作后，旧模型拒绝继续路由，需重新收集标注并训练。第一版学习的是**已知边 ID 的选择**，不能对新边零样本泛化；图外语义联想，如“鸡、篮球 → 蔡徐坤”，仍需具体训练样本和可解释关系，不能从普通向量加法直接得到。
