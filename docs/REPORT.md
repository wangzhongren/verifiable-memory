## 一句话结论

**假设成立**：八轮实验的纪律（显式寻址、失败留痕、独立核验）可以直接组装成一个可用的可教学记忆系统——LLM 在验证边界上游解析自然语言，边界内只有确定性代码，因此每个答案带证据链、每次纠错带零附带损害证明、整个会话能在独立进程逐位重放，全程无需任何训练。

| 时刻 | 答案 | 证据 |

## 值得留档的机制事实

- **错误也是证据**：错误操作（如对已存在名称 teach）如实落日志、哈希链不断、无副作用；replay.py 连错误消息都逐字复现，verify.py 检查错误条目无状态变化。
- **独立性边界兑现**：verify.py 只与 store.py 共享两个哈希原语（canonical_json / sha256_string），原语执行、槽位应用、证书复核全部独立实现。开发中这已经产生回报：verify.py 曾按"最终程序"重算历史执行而漏掉纠错时序，被 checks.py 当场抓获（`op-002: 答案 3214 ≠ 独立重算 1432`）——两套实现互查正是设计目的。
- **解析层可以答错但越不过词表**：LLM/后备文法产物必须过 `validate_op`（op 类型、原语词表、输入格式白名单），再过会话的类别锁（teach/ask/correct 与 op 类型一致），再过 store 的存在性/容量/种类检查。三道锁全部在验证边界上。
- **篡改检测实测**：手改 session.json 中任一记录内容 → Session.load 因哈希链断裂/终态不符拒绝加载（checks.py 覆盖）。

## 与八轮实验的关系

- 核心寻址采用**显式命名槽位**（名称即键、纠错=同槽覆盖）——直接落地"显式寻址赢"的结论；系统里没有任何学习型软寻址组件。
- 失败语义继承第 7 轮引擎契约：执行器对非法输入/未知原语抛错，宿主不得代为修复。
- 第 8 轮读写对偶（DᵀA=I）的工程对应物：这里的"读"是按键取整条记录（精确对偶于写入），不存在部分读出，因此没有串扰问题——这是显式寻址在可验证性上的额外红利。

## 局限（如实）

1. 执行器是符号的，答案 100% 正确是平凡事实；系统的全部难度在解析层（LLM）与可验证性机制。
2. 16 命名槽位、名称精确匹配：用户必须记住（或查询）名称；没有模糊寻址（被实验否决为主线）。
3. 无 key 环境下解析限于后备文法的固定句式。
4. `cli.py` 默认会话即 demo/session.json：在 demo 证据生成后再用默认路径执行 teach/ask 会追加条目，使 replayed/verify 过期——复核证据请用 `--session` 指到别处（README 已注明）。

## 附录（2026-09-22）：SQLite 工作存储

为"做成 CLI + 技能供日常使用"铺路，存储层升级为**SQLite 工作存储 + JSON 证据格式**双层（新增 `storage.py`，核心五文件 store/executor/proof/parser/verify 与 verify.py 独立性边界一字未动）：

- `memory.db`：ops 表一行一操作、只追加，哈希链住在行里；state 表为可重建的物化缓存；WAL + BEGIN IMMEDIATE；
- **并发协议**：落库前在事务内核对链头，被并发进程抢先则重载日志重试（乐观并发）。checks.py 新增真子进程并发压力测试（5 进程 × 3 teach 同时写）：15/15 全部落库、无丢失、链严格线性——单 JSON 时代"后写吞先写"的竞态正式关闭；
- **缓存纪律**：state 缓存可被手改的攻击面用"重放 vs 缓存"核对封死（篡改测试覆盖 ops 行与 state 行两个方向）；meta/entries/cache 三读必须同处一个 WAL 读事务（开发中抓到并修掉了分离读导致的假阳性）；
- **证据契约不变**：`cli.py export` 导出 canonical session.json，同一操作序列在两后端下证据文件**逐字节一致**（断言在 checks.py）；replay/verify 直吃导出文件、永不直读 DB，灵魂样例 3214→1432 在新后端下复现（`demo/SQLITE_TRANSCRIPT.md`）；
- 一处测试修正：并发压力原设计 18 条超出默认 16 槽，2 条被正确拒绝——系统无误，测试改为 15 条。

## 附录二（2026-09-22 晚）：32k 扩容改造

针对"扩到 32k 槽是否可行"的三个挡路件，全部落地（自检 32→41 项）：

1. **证书 v2 瘦身**（proof.py/store.py）：写证书从全槽哈希表 O(N)/写（32k 下 ~5.9MB/写，不可行）降为 O(1)——只存目标槽前后哈希 + 状态哈希 + `created`。语义重心转移：`zero_collateral` 变成**写入时的构造断言**（apply_write 只赋值目标槽一个键）+ **verify.py 独立重放的全量证实**（第二套实现重建全槽 diff，对断言逐条复核，状态哈希也改用独立重算值——顺带修复了 v1 路径中状态哈希自引自证的弱点）。v1 证据双格式兼容。
2. **快照 + 尾部重放**（storage.py/session.py）：state 表兼任快照实体（与每个写事务同步更新），每 512 条 op 推进一次检查点（O(1)，只是给快照位置盖时间戳）；load 走"快照 O(N) 重建 + snapshot_hash 锚 + 尾部重放"，每条命令不再背 O(总日志)。快照段内的日志篡改由 load **有意放行**、由离线 replay 全量重放负责——checks.py 实测了这一分工（放行 ✓、离线抓住 ✓）；快照缓存本身的篡改仍被 snapshot_hash 锚当场抓住。首个检查点之前自动退化为全量重放路径（state 缓存领先于空锚）。
3. **检索**（cli.py）：`search 关键词`——名称与内容的确定性子串匹配。32k 名字"记不全"的答案仍是显式机械装置（维基搜索框同款），检索是导航不落日志，引用所选名称的操作才落日志。

**证据契约全程未动**：导出格式、逐字节等价断言、replay/verify 的输入全部不变；改动后跨进程四步、灵魂样例 3214→1432、并发压力、证据等价全部原样通过。改清单：proof/store/storage/session/cli/replay/verify/checks——验证边界的语义（六种 op、三道锁、哈希链结构）零变化。

未做（按需）：Merkle 增量哈希（写延迟敏感时上，当前 O(N) 状态哈希在单命令模式下 ~几十 ms 可忍）；FTS5（LIKE 子串在 32k 行毫无压力，中文分词还添乱）。

## 附录三（2026-09-22）：真实场景 field test

四个真数据场景（field_test.db 独立库 + memory.db 真实启用），数据取自八轮实验的真实结论与数字：

- **A 科研结论库**：教入第7/8轮结论与数字（含故意记错的 23.54%→纠错 25.34%，第1版留痕可审计）；`search 对偶`/`search 控制器` 命中如预期；
- **B 环境真实性**：规则执行拿 Python 版本号 3147 当输入（交换前两位+首位加一 → **2347**，与手工预判一致，逐步 trace 留证）；查询不存在名称被拒且列出已知槽位（退出码 1）；**两进程并发写**各得一个 op、哈希链严格相扣；从 /tmp 跨目录访问同一记忆库成功；
- **C 证据三连**：export→replay→verify 全过，零附带损害独立证实；体积实查：12 条操作 db=40KB、证据=11.7KB（v2 证书 O(1) 的直接体现）；
- **D 真实启用**：定案08/数字07 两条真实研究结论教入日常 memory.db（第1版留证）。

**现场测试立功，抓到两个真 bug 并修复**：

1. verify.py 把灵魂样例断言写死——任何不含 规则07/1234 的真实会话都会被误判失败。改为"有则断言、无则跳过"（`soul_checked` 字段），demo 验收路径不受影响；
2. **replay.py 的错误条目重放**：比对错误消息时误加了 `ERROR: ` 前缀、且错误写条目根本不尝试重放。此前所有测试场景恰好零错误条目，第一次真实错误（查询不存在的实体）当场炸出。修复：错误条目必须真重放并以裸消息逐字比对；checks.py 的跨进程管线加入错误条目防复发。

教训一句话：**错误路径的测试覆盖必须包含"错误本身过全管线"**——演示场景全是成功路径，真实使用第一天就会踩到失败语义。自检扩至 42 项。

## 附录四（2026-09-22）：批量导入 + 跨环境可用

新增 `cli.py import`：JSONL（或 JSON 数组）→ 逐条 teach/correct op。架构铁律：**导入必须过验证边界**——每条都是真实留痕的操作（`source='import:<文件名>'`，utterance 带文件与行号），坏条目先验形、不落日志；没有任何绕过日志的直插，导入后的库照常 export/replay/verify。选项：`--on-conflict skip|correct`、`--dry-run` 预检；JSONL 坏行按行报告、不拖垮整批（开发中抓到并修复"坏行解析在收集阶段拖垮全批"的 bug）。跨环境可用分三层：①本机跨项目——技能用户级，所有项目共用同一 memory.db；②跨机器——单文件 SQLite 拷走即可，`--session` 指过去；③跨工具——CLI 即接口，任何能跑 shell 的 agent 可用。

实测：`import_knowledge.jsonl`（八轮实验真实知识 8 条）→ 预检 → 导入日常 memory.db（11 槽/16 条日志）→ 从 /tmp 跨目录查询/检索即用。自检扩至 46 项全绿。
